# Elasticsearch 9.5.1 logsdb vs logsdb_columnar compression test

## Scope changes (2026-08-17)

- NDJSON is **generated by this project** (not supplied by the user).
- Every index create **validates** settings and mappings before ingest.
- On **Basic** license, compare `_source` modes **`stored` vs `disabled`**.
- Cluster: existing Docker container `es-bench` (Elasticsearch 9.5.1, license `basic`, security off). Data lives on `/mnt/docker-data/es-data`.
- Generated data lives on `/mnt/docker-data/testcolumnar/` (root filesystem is only ~11GB free).

## Scenarios

| ID | License | `index.mode` | `index.mapping.source.mode` | Message field |
|----|---------|--------------|-----------------------------|---------------|
| A | basic | `logsdb` | `stored` | `text` |
| B | basic | `logsdb` | `disabled` | rejected at create |
| C | basic | `logsdb_columnar` | `columnar_stored` | `text` |
| D | basic | `logsdb_columnar` | `disabled` | rejected (only `SYNTHETIC`, `COLUMNAR_STORED`) |
| F | basic | `standard` | `stored` | `text` |
| G | basic | `standard` | `disabled` | `text` |
| E | trial | `logsdb_columnar` | `synthetic` | `pattern_text` |

Validation (2026-08-17): logsdb cannot disable `_source`; logsdb_columnar does not support `stored` or `disabled`. The Basic stored vs disabled comparison therefore uses `standard` indices (F/G). Columnar auto-flattens object mappings to leaf names such as `host.name`.

`logsdb_columnar` does not support traditional `stored` `_source`. Scenario C uses `columnar_stored`, the Basic-license equivalent.

## Mapping rules

- Same field set in every index.
- Structured fields: `keyword` / `long` / `date` / `ip` (no `text`+`keyword` multi-fields).
- Free-text: `message` as `text` (Basic) or `pattern_text` (Enterprise).
- `"dynamic": "strict"` so all indices ingest the same fields.
- Users can query individual fields (`term` / `range` / `match`).

## Measurement

- Raw size = generated NDJSON bytes.
- Index size = `pri.store.size` after `_refresh` + `_forcemerge?max_num_segments=1`.
- Compression ratio = `raw_bytes / pri.store.size`.
- Field breakdown via `_disk_usage`.
