# Elastic 9.5.1 logsdb / logsdb_columnar 压缩测试方案

## 相对原计划的变更（2026-08-17）

1. **NDJSON 由本项目生成**（约 5GB 应用/HTTP 日志），不使用外部文件。
2. **每次写入 settings/mappings 后立即校验**：`index.mode`、`source.mode`、`message` 类型、无 `text`+`keyword` 双写、抽样文档可索引。
3. **Basic 许可重点对比 `source=stored` 与 `source=disabled`**。
4. 复用已运行的 Docker 容器 `es-bench`（Elasticsearch 9.5.1，Basic，安全关闭）。数据目录：`/mnt/docker-data/es-data`。生成数据放在 `/mnt/docker-data/testcolumnar/`（根盘空间不足）。

## 测试矩阵

| 场景 | License | index.mode | source.mode | 自由文本 |
|------|---------|------------|-------------|---------|
| A | basic | logsdb | stored | text |
| B | basic | logsdb | disabled | 创建阶段已拒绝 |
| C | basic | logsdb_columnar | columnar_stored | text |
| D | basic | logsdb_columnar | disabled | 创建阶段已拒绝（仅允许 SYNTHETIC / COLUMNAR_STORED） |
| F | basic | standard | stored | text |
| G | basic | standard | disabled | text |
| E | trial | logsdb_columnar | synthetic | pattern_text |

校验结论（2026-08-17）：`logsdb` 不允许 `_source` disabled；`logsdb_columnar` 不支持 `stored`/`disabled`。Basic 下 stored vs disabled 对比改在 `standard` 索引上进行（F/G）。`logsdb_columnar` 会把对象字段拍平为 `host.name` 这类叶子字段，查询路径不变。

## 约束

- 三/五套索引写入同一批文档。
- 结构化字段可单独 term/range 查询；`message` 用 match。
- 禁止同一字段 `text` + `.keyword` 重复存储。
- 写入后 forcemerge 再测压缩率。
