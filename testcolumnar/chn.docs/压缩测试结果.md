# Elasticsearch 9.5.1 压缩测试结果

独立集群：`es-testcolumnar`（端口 9201，未使用被其他压测占用的 `es-bench`）。数据：自建 NDJSON **11,964,127** 条，**5,368,709,228 字节**（约 5.00 GiB）。每套 mapping 在写入前均做校验。写入后 `_forcemerge` 到 1 个 segment 再测 `pri.store.size`。字段级 `term` / `range` / `match` / ES|QL 均通过。无 `text`+`keyword` 双写。

## 配置校验结论

- **logsdb + source=disabled**：拒绝。`_source can not be disabled in index using [logsdb] index mode`
- **logsdb_columnar + source=disabled**：拒绝。仅允许 `SYNTHETIC`、`COLUMNAR_STORED`
- **logsdb_columnar** 不支持传统 `stored`；Basic 下对应的是 `columnar_stored`（对象会被拍平为 `host.name` 等叶子字段，查询路径不变）
- Basic 下若请求 `synthetic`，索引能创建，但实际 **静默落成 `COLUMNAR_STORED`**
- `index.mapping.synthetic_source_keep` 不能用在 `logsdb_columnar`
- Trial 下 `synthetic` + `pattern_text` 校验通过

因此 Basic 上 **stored vs disabled** 只能在 `standard` 索引对比（场景 F/G）。

## 压缩率（相对 5.00 GiB 原始 NDJSON）

| 索引 | License | mode | _source | message | 磁盘 | 占原始 | 压缩比 |
|------|---------|------|---------|---------|------|--------|--------|
| test-standard-stored | basic | standard | stored | text | 2.17 GiB | 43.3% | 2.307× |
| test-logsdb-stored | basic | logsdb | stored | text | 2.03 GiB | 40.6% | 2.462× |
| test-logsdb-columnar-stored | basic | logsdb_columnar | columnar_stored | text | 1.46 GiB | 29.2% | 3.428× |
| test-standard-disabled | basic | standard | disabled | text | 1.40 GiB | 28.0% | 3.570× |
| test-logsdb-columnar-synthetic | trial | logsdb_columnar | synthetic | pattern_text | **0.69 GiB** | **13.7%** | **7.294×** |

## 解读

1. Basic 上 logsdb（stored）比 standard stored 略小（2.03 vs 2.17 GiB）。
2. Basic 上 logsdb_columnar（columnar_stored）再小一截到 1.46 GiB，主要是去掉 inverted index / points，但 doc_values 里仍有一份列式 `_source`（约 1.36 GiB）。
3. Basic 上 **standard + disabled**（1.40 GiB）甚至略小于 columnar_stored，因为完全不存 `_source`；代价是 `_source` 无法返回（字段查询仍可用）。
4. Enterprise trial 的 **synthetic + pattern_text** 最小：0.69 GiB，约为 logsdb stored 的 1/3、原始 JSON 的 13.7%。
