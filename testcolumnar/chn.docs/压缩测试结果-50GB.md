# 50GB 最终压缩结果（Elasticsearch 9.5.1）

独立集群 `es-testcolumnar:9201`。数据：**119,642,150** 条，**53,687,091,267 字节（50.00 GiB）**，与 5GB 同一套 mapping。五套索引文档数一致，查询校验通过。

## 压缩率

| 索引 | mode / `_source` | message | 磁盘 | 占原始 | 压缩比 |
|------|------------------|---------|------|--------|--------|
| test-standard-stored | standard / stored | text | 21.55 GiB | 43.1% | 2.320× |
| test-logsdb-stored | logsdb / stored | text | 20.28 GiB | 40.6% | 2.465× |
| test-logsdb-columnar-stored | logsdb_columnar / columnar_stored | text | 14.46 GiB | 28.9% | 3.458× |
| test-standard-disabled | standard / disabled | text | 13.25 GiB | 26.5% | 3.775× |
| test-logsdb-columnar-synthetic | logsdb_columnar / synthetic | pattern_text | **6.75 GiB** | **13.5%** | **7.405×** |

50GB 与 5GB 的压缩比几乎同趋势，略更好（模板重复更多）。Trial 的 synthetic + `pattern_text` 仍是最小，约为 logsdb stored 的 **1/3**。

## 示例 event

原始 NDJSON / `logsdb` stored `_source` 一致：

```json
{
  "@timestamp": "2026-08-01T00:00:00.008Z",
  "host": { "name": "web-01" },
  "service": { "name": "catalog-api", "version": "3.4.1" },
  "log": { "level": "INFO" },
  "http": {
    "request": { "method": "GET" },
    "response": { "status_code": 200, "bytes": 22990 }
  },
  "url": { "path": "/api/v1/users/773246" },
  "source": { "ip": "10.18.216.9" },
  "event": { "duration": 2234000000 },
  "trace": { "id": "17fc695a07a0ca6e3b8faa1837f8a88b" },
  "message": "Request completed method=GET path=/api/v1/users/773246 status=200 duration=2234ms bytes=22990"
}
```

`logsdb_columnar` 下 `_source` 会拍平为 `host.name`、`http.response.status_code` 等叶子字段，查询路径不变。
