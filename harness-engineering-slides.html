Harness Engineering Practice
The Ratchet Principle

Every agent mistake is a permanent signal. Harness engineering tightens one notch each time the agent slips.

Mistake 1
Agent ships PR with commented-out test
→
AGENTS.md rule
"Never comment out tests. Delete them or fix them."
Mistake 2
Agent runs destructive command (rm -rf)
→
Hook added
Blocks rm -rf, git push --force, DROP TABLE before execution
Mistake 3
Agent gets lost in a 40-step task
→
Orchestration
Split into planner subagent + executor subagent
Mistake 4
Agent keeps finishing broken code
→
Loop hook
Typecheck + lint + tests after every edit. Failures injected into loop.
💬
"Every line in a good AGENTS.md should be traceable back to a specific thing that went wrong." — Addy Osmani
Core Discipline
Context Engineering: The Harness's Core Job

Harnesses are largely delivery mechanisms for good context engineering. Context is scarce — every token must earn its place.

1
Connect
Unify all enterprise data — tickets, logs, documents, feedback — in one datastore. Index, clean, label via ingest pipelines. RBAC controls who sees what.
2
Retrieve
Hybrid search combines vector (kNN) + lexical (BM25). Semantic reranking re-scores top results. Just-in-time context — retrieve only what the agent needs right now.
3
Structure
ES|QL tools give agents precise, parameterised queries. Custom tools encode business logic. MCP servers expose external capabilities. Clear tool descriptions = clear agent behaviour.
4
Adapt
Memory files persist across sessions. Compaction offloads stale context. Progressive disclosure loads skills only when needed. Evaluation metrics drive continuous improvement.
⚠
Context rot: models get worse as the context window fills. Counter-techniques: Compaction (summarise & offload) · Tool-call offloading (keep head/tail, filesystem the rest) · Skills with progressive disclosure (load only when needed)

Execution Pattern
The Agent Loop: ReAct + Hooks

The core execution pattern: Reason → Act → Observe → Repeat. Hooks intercept at every lifecycle point to enforce constraints.

REASON

LLM analyses context, plans next action

▼

ACT

Agent calls a tool — search, ES|QL, bash, API

▼

OBSERVE

Tool output fed back into context. Loop repeats.

⟲
Continues until goal reached or stopped
⛨ Hooks — the safety system
Before tool call
Block destructive commands — rm -rf, DROP TABLE, git push --force never execute
After file edit
Run typecheck + lint + tests automatically. Failures injected back into the reasoning loop.
Before commit
Require human approval for high-risk changes — git push, deploy, schema migration
On session start
Inject AGENTS.md & memory files — agent inherits all accumulated rules
On context limit
Compaction — summarise & offload stale context. Preserve head/tail, skeleton of progress.
On ES|QL query
RBAC enforced — agent can only query indices within its permission scope

Framework
Harness Maturity Model

From raw model to production-grade agent — the harness maturity journey.

Level 1
Raw Model
  • Chat interface only
  • No tool execution
  • No persistent state
  • Copy-paste workflow
  • No audit trail
  • Every mistake is a surprise
Level 2
Basic Harness
  • System prompt + AGENTS.md
  • Filesystem access
  • Basic tool calling
  • Single agent, one session
  • Manual error recovery
  • Ad hoc fixes after failures
Level 3
Engineered Harness
  • Hooks enforce rules automatically
  • Subagents: planning + execution
  • Compaction for long sessions
  • Memory persists across sessions
  • Typecheck/lint/test in loop
  • Every mistake → permanent rule
Level 4
Production Platform
  • Multi-agent orchestration
  • Full observability + cost tracking
  • RBAC + data sovereignty
  • MCP + A2A integration
  • Continuous evaluation
  • Harness-as-a-Service (HaaS)
