Part 3
ECS & Streams
The common data language and AI-powered log management
Elastic Common Schema (ECS)
The open-source specification that makes O11y and Security data interoperable — the single biggest enabler of cross-domain analytics
Standardised Fields
@timestamp, event.*, host.*, source.*, destination.*, user.*, process.* — same names, same types, everywhere. All Elastic Agent integrations auto-map to ECS.
Cross-Domain Content
Dashboards, detection rules, and ML jobs work across any ECS-compliant data. A security rule can run on O11y data. An APM dashboard can include security context.
OpenTelemetry Convergence
ECS donated to OpenTelemetry (2023). ECS and OTel Semantic Conventions converging into a single open schema for both O11y and Security.
Security-Required ECS Fields
@timestamp   ecs.version   event.kind   event.category
host.name   host.id   process.name   process.pid
source.ip   destination.ip   user.name   user.id
O11y Fields Also Standardised
service.name   trace.id   transaction.id
http.request.method   http.response.status_code
log.level   error.message   container.id

Use Case 1: Cryptomining Attack Detection
Universal Profiling + Streams + SIEM — CPU spike to containment in 15 minutes
Scenario
E-commerce checkout service suddenly experiences 99% CPU utilization during peak hours. DevOps notices slow response times, but root cause is unclear.
O11y Signal
Universal Profiling: container process at 99% CPU on crypto hashes. Metrics: sustained spike on 3 pods for 18 min.
Security Action
ECS data triggers cryptomining detection rule. AI Assistant IDs CVE + MITRE ATT&CK T1496. Workflow auto-isolates pods.
Timeline
T+0 Universal Profiling: 99% CPU on crypto hash ops across 3 pods
T+2 Streams: Significant Event — unexpected process spawn via cron
T+7 SIEM rule fires. AI Assistant: CVE + MITRE T1496
T+10 Security team validates. Correlation: external IP from threat intel
T+15 Automated workflow isolates pods, kills processes. CPU back to 12%
Detection Flow & Evidence
1. O11y Metrics Alert
Detection Query: system.process.cpu.total.pct > 0.95 for 5 minutes
process.name: "xmrig" | cpu.pct: 0.99 | pod: "checkout-7f8b9"
→ Triggered investigation into high CPU process
2. Streams Detection Rule
Detection Query: event.type: process_start AND parent.name: crond
event.type: "process_start" | parent: "crond" | child: "xmrig"
→ Identified unauthorized process spawn pattern
3. Security Correlation
Detection Query: destination.ip: * AND process.name: xmrig
threat.indicator.ip: "185.220.101.x" | matched: cryptomining_pool
→ Confirmed C2 communication to known mining pool
4. SIEM Enrichment
Detection Query: JOIN threat_intel ON destination.ip
ecs.version: "8.14" | event.category: ["process","malware"] | mitre: "T1496"
→ Auto-triggered isolation workflow via MITRE mapping
✓ Detected via O11y CPU spike → Contained via Security workflow → MTTR: 15 min (vs 4 hrs manual)
